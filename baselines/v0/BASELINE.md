# V0 Baseline (frozen 2026-09-28)

This is the frozen reference point for V0. Everything after this (V1 retrieval, V2 outcome memory) is compared against it. Don't edit the run files in this folder. Add new runs next to them instead.

## H1 verdict

> **H1: Pass, provisionally.** V0 produces useful first-draft answers from an RFP and a fact sheet. It routes known knowledge gaps to an SME and shows enough of its sources for a person to review. The remaining issues are quality improvements, not evidence that the workflow is useless.

This does **not** establish that the AI's answers are correct. Correctness is measured systematically in V4 ([PRD §15.1](../../../PRD_RFP_MEMORY_ASSISTANT.md#151-tier-1-thesis-metrics-mvp-synthetic-data)).

**Correction (2026-09-28, during V1 work):** the two sample files were regenerated by accident. Word and Excel files embed save timestamps, so their **byte** hashes changed. Their **content did not**:
- The generator code for them was unchanged.
- The parsed text has the same character counts as in the V0 runs.
- All 30 questions from the frozen runs are found verbatim in the regenerated text.

The freeze is therefore defined by the **parsed-text hash** (what the pipeline actually reads). To check it, run `parse_document(...)` and hash `.text`. `make_samples.py` now refuses to overwrite existing samples unless run with `--force`.

## Known weaknesses, kept as evaluation cases

These go into the V4 evaluation set. They're what the systematic evaluation must measure, and none of them is a V0 bug to patch now.

| ID | Case | Evidence | What V4 must measure |
|---|---|---|---|
| **EC-01** | **Valid citation, unsupported claim.** A negative inference presented as fact | v0.2, 6.2: "we do not offer a prebuilt connector for Jack Henry Symitar", citing FACT-020, which only lists the connectors that exist. Check 1 passed it. Fixed by v0.3 rule 4, but only one run supports that | Unsupported-claim rate under check 2 (evidence support); the negative-claim rate across repeated runs |
| **EC-02** | **Incomplete use of relevant facts** | 3.1 SSO omitted OIDC, Okta and Google in v0.1 and v0.2, and included them in v0.3. 6.1 used both API facts only in v0.2 | Recall of relevant facts per answer, across repeated runs |
| **EC-03** | **The SME decision varies from run to run** | 3.5 was Needs SME in v0.1 and grounded in v0.2/v0.3. 5.1 was grounded in v0.1/v0.2 and Needs SME in v0.3 (it asked for credit percentages) | Needs-SME precision (is the gap real?) and its stability across runs |
| **EC-04** | **Extraction text varies** | "MANDATORY:" and "(Maximum N words)" were stripped from question text in some runs and kept in others. The prompt was unchanged | Extraction consistency; repeated runs are required (frozen protocol, D-12) |
| **EC-05** | **Terse answers** | Answers use roughly 15–30% of stated word limits (for example 19 words against a limit of 100) | Reviewer judgment: is it complete enough? Compare a stronger model (`gemini-3.8-flash`) and higher effort |
| **EC-06** | **SME questions that restate the buyer's question** | "Does our solution support … SCIM 2.0?" | Usefulness of SME questions (reviewer rating) |

**Methodological lesson:** single runs can't separate prompt effects from run-to-run variation (EC-03, EC-04). From now on, compare prompts or models only with repeated runs.
